(async) WScreenctl(optopt) → {Promise.<Server>}

Description:

  • 啟動 w-screenctl 服務，對外提供 REST API 控制作業系統桌面（滑鼠、鍵盤、截圖）與 Chrome 瀏覽器

    跨平台支援：Linux 走 xdotool / ImageMagick，Windows 走 w-mousekey / AHK；Chrome 控制全平台皆透過 Playwright

    /chrome/open 預設以 headless 啟動；需要實體視窗（系統級滑鼠鍵盤 / 系統截圖操作 chrome 時） 得於 payload 送 opt.headless: false

    零信任設計：caller 可任意 retry / 中斷 / agent swap，server 維持自洽狀態。所有 chrome lifecycle 透過 ChromeManager 序列化；所有路由經由 routeFactory 統一錯誤處理；所有 payload 經 Joi 驗證。

    預設安全（1.0.26 之後的版本起；破壞性變更）：

    • 只綁 127.0.0.1；綁其他位址須自行提供 token，否則拒絕啟動（丟出 code 為 SCREENCTL_CONFIG 之 Error）
    • 除 GET /health 外所有端點須 Authorization: Bearer <token>（定時比較）。token 未給時啟動自動產生並寫入 token 檔
    • 預設不開 CORS；Host 標頭須為本機名稱（擋 DNS rebinding）；帶 Origin 之請求預設一律拒絕，可由 allowedOrigins 放行白名單
    • /chrome/evaluate 預設關閉（403），須 enableEvaluate 顯式開啟 新增之安全選項優先序皆為：選項 > 環境變數 > 預設（port、fdUserData 維持既有之環境變數優先）

    操作紀錄（預設開啟）：每次控制動作（系統級 /keyboard、/mouse、/screenshot，與 /chrome/*）與每次被閘門拒絕之請求（401／403）各記一行 JSON 到紀錄檔。 內容：時間（ISO）、方法、路徑、來源 IP、狀態碼、耗時、結果（ok／code）、不含機敏內容之參數摘要（座標、鍵名可記；/keyboard/type 與 /chrome/keyboard/type 只記文字長度； /chrome/evaluate 只記 script 長度與 SHA-256；網址去除查詢字串；單一可印字元之按鍵不記字面）；拒絕事件記拒絕原因（denied）。token、請求本體一律不記。 紀錄檔超過上限即輪替；寫檔失敗不影響請求（console 警告一次）。可關閉系統級端點（enableSystem: false）供只需操控 Chrome 之情境。

createAuditLogger(cfg, depsopt) → {Object}

Description:

  • 建立紀錄寫入器：同步 append（一筆一行，不交錯）、超過 maxBytes 即輪替（保留 keep 份舊檔）； 任何寫檔失敗都不丟例外（不得使請求失敗），連續失敗只警告一次，恢復成功後再失敗才再警告

    • 檔案於首次寫入才建立（目錄 0700、檔案 0600，POSIX；既有檔案若權限寬於 0600 會於首次寫入後收緊，既有目錄不改）
    • 每次寫入前重新取得實際檔案大小（不快取）：部分寫入、外部截斷、同檔多寫入者都不會讓上限失準
    • 輪替：先把目前檔改名為暫存檔（此步失敗時其他檔都沒動，之後可重試），再 file.(keep-1)→file.keep…，最後暫存檔→file.1；中途失敗會把目前檔還原。 keep=0 則超過上限即清掉重寫。首次寫入時順便刪除超過 keep 份之舊輪替檔（調降保留份數後會收斂）。輪替失敗時丟棄新紀錄，使檔案維持有界
    • 單筆即超過上限者仍完整寫入（不拆行、不丟棄）。調降 maxBytes 後，既有的較大舊檔不會被截斷，隨輪替自然汰換
    • append 失敗（可能留下半行）後，下一筆前置換行，使該筆仍可獨立解析
    • redact：目前的 token 等機密全文；寫入前會自序列化後的整行清除（含 JSON 跳脫形式），不論它經由哪個載體進到紀錄項 一個紀錄檔請只給一個實例寫入（預設檔名含 port 與非預設位址）。

createGate(cfg) → {Object}

Description:

  • 建立 Hapi 閘門

    onRequest（先於路由比對，涵蓋所有請求含 404 與 CORS 預檢）：

    • Host 標頭須在白名單（綁迴路時為本機名稱）→ 擋 DNS rebinding
    • 帶 Origin 之請求須在 allowedOrigins（預設空＝一律拒絕）→ 擋跨站 onPreAuth（路由比對後，先於 payload 解析與 Joi 驗證）：
    • options.app.public === true 之路由（目前僅 GET /health）免 token
    • 其餘一律須 Bearer token（預設拒絕，不特別放行任何 method）
    • options.app.feature === 'evaluate' 且 evaluate 未開啟 → 403 EVALUATE_DISABLED
    • options.app.feature === 'system' 且系統級關閉（enableSystem=false）→ 403 SYSTEM_DISABLED 每次拒絕都把原因碼記在 request.app.denied（操作紀錄用） 注意：Hapi 內建之 notFound 與 CORS 預檢（OPTIONS）特殊路由不經 onPreAuth（server.ext 於建立後才註冊， 不會重建特殊路由之生命週期；api-security 之預檢測試鎖定此行為）。預檢因此不需 token，且已受 onRequest 的 Origin／Host 檢查； 它只回 CORS 標頭，不執行任何 handler。
